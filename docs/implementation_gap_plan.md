## 实现顺序

1. 版本管理基线：配置 remote，保留大文件在本地资料目录，提交代码与轻量资料。
2. 后端测试先行：规则导入、运行时 DB 规则、RAG 文件入库、合规材料、未实现 API、处方动作候选、专家详情。
3. 数据模型与迁移：扩展动作、知识文档/切片元数据、合规材料。
4. 导入脚本：风险规则、合规材料、docs 业务库、rag_data allowlist 重建索引。
5. 业务服务：DB 规则进入风险流程，RAG 文件解析与来源返回，处方生成纳入已审核动作，补审计。
6. API：合规材料、未实现模块、专家审核详情。
7. 前端：展示合规材料、专家审核详情和操作、未实现模块提示。
8. 验证：后端测试、前端 lint/test/build、RAG 构建 smoke、关键 API smoke。

## 当前范围说明

- PaddleOCR 仅在遇到扫描件/图片型资料且本地文本解析失败时作为可选 OCR 后端启用；本次先提供可配置接口与清晰错误，不把 OCR 服务硬编码进主流程。
- rag_data 中存在超过 GitHub 单文件限制的大 PDF。原始文件不删除，但默认不直接纳入 Git 提交；提交 manifest、脚本和索引能力。
- docs 合规材料文件标注为 expert review draft，第一版作为“专家审核草案”展示，仍需用户提供正式法务/伦理审核版本。
