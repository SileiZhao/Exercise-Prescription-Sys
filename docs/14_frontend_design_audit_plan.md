# 前端与交互设计审查改进计划

## 设计判断

当前系统功能完整，但原始页面偏“功能堆叠”：表单、表格、图表已经能用，却缺少医疗健康中台应有的第一屏决策、状态解释、任务优先级和审计感。本轮改造采用统一产品语言：先展示安全/审核/导出/就绪结论，再进入具体操作。

## 页面改进计划

| 页面 | 原问题 | 改进方向 | 本轮落地 |
| --- | --- | --- | --- |
| `/` 首页 | 四个入口卡片像普通菜单，缺少系统边界 | 改成角色控制台入口，展示 R2 审核、R3 阻断、科研脱敏治理 | 已落地 |
| `/login` 登录 | 单卡片表单，医疗系统信任感不足 | 双栏认证入口，左侧展示角色、风险边界、审计治理，右侧表单 | 已落地 |
| `/register` 注册 | 注册后流程不清楚 | 说明普通用户注册后进入知情同意、六类数据、风险结果 | 已落地 |
| `/auth/change-password` 首次改密 | 像孤立表单 | 强调改密前访问受限、改密后重新登录、令牌刷新 | 已落地 |
| `/user/dashboard` 用户看板 | 指标优先，用户不清楚今天能否运动 | 第一屏改为“今日通行证”，明确能否运动、原因、下一步 | 已落地 |
| `/user/health-data` 建档 | 六类数据表单堆叠 | 改成分步建档工作台，固定说明采集目的和红旗字段 | 已落地 |
| `/user/risk-result` 风险结果 | 分型与风险边界混在一起 | 改成风险判定报告，先解释 R0-R3，再展示分型标签 | 已落地 |
| `/user/prescriptions` 处方 | 生成、审核、导出、版本混在一张卡 | 改成处方发布面板，训练可见性和导出锁定前置 | 已落地 |
| `/user/today` 今日运动 | 红旗信号埋在反馈表单中 | 拆成运动前安全闸门和运动反馈，红旗信号触发顶层阻断 | 已落地 |
| `/user/phase-report` 阶段报告 | 图表优先，阶段决策不突出 | 第一屏展示进阶/维持/降负荷/复核/红色预警决策 | 已落地 |
| `/expert/dashboard`、`/expert/reviews` 专家审核 | 队列、证据、动作分散 | 分诊队列、工作桶、证据 Tabs、发布动作条、状态机 | 已落地 |
| `/admin/dashboard` 管理看板 | KPI 像普通 dashboard | 改成运营指挥台，先看上线阻断、R2 积压、R3 转介、RAG 状态 | 已落地 |
| `/admin/templates` 模板库 | 裸 CRUD，模板治理意义弱 | 加入治理决策条、模板批准状态、版本/审计入口 | 已落地 |
| `/admin/exercises` 动作库 | 动作表字段多，审核优先级弱 | 强化待审核动作、禁忌、停止信号和适宜人群治理 | 已落地 |
| `/admin/knowledge` 知识库 | RAG 状态不前置 | 强化启用文档、索引重建、检索验证和合规材料说明 | 已落地 |
| `/admin/rules` 风险规则 | DSL 表单和测试工具割裂 | 改成规则构建器，启用数、红色规则、草稿数先展示 | 已落地 |
| `/admin/clusters` 聚类模型 | 容易误读为风险判定模型 | 改成模型生命周期页，强调只做画像和模板匹配 | 已落地 |
| `/admin/users` 用户专家 | 用户、机构、专家资料散乱 | 改成身份治理台，展示启用用户、专家资料、机构隔离 | 已落地 |
| `/admin/audit-logs` 审计日志 | 单表格无上下文 | 改成可追责记录台，强调资源、操作者、元数据和时间 | 已落地 |
| `/research/dashboard` 科研总览 | 图表像普通分析页 | 加入脱敏样本、本人任务、聚合视图说明 | 已落地 |
| `/research/cluster-analysis` 科研分型 | 缺少脱敏边界说明 | 分型规模与风险叠加放入脱敏分析区 | 已落地 |
| `/research/intervention-effects` 干预效果 | 多图表缺少治理语境 | 明确趋势来自脱敏聚合数据 | 已落地 |
| `/research/export-jobs` 导出任务 | 导出像普通下载工具 | 加入审批通过、限时下载、已下载关闭入口说明 | 已落地 |
| `/admin/research-export` 科研审批 | 审批和预览混杂 | 改成导出审批队列，审批意见、样本量、过期时间前置 | 已落地 |

## 后续精修项

1. 为高频表格补充列密度配置、固定操作列和保存后的行级反馈。
2. 为专家审核、规则测试、科研审批补充更细的骨架屏。
3. 根据真实演示账号数据补齐空态文案，避免演示时出现“暂无数据”无行动路径。
4. 在浏览器视觉验收后，对 390px 移动端表单按钮和表格横滚做第二轮细节调整。
